## 预览和维护

直接用浏览器打开当前稿的 HTML，或从仓库根目录启动静态预览（只公开原型目录）：

```sh
python3 -m http.server 4173 --bind 127.0.0.1 --directory docs/app-design/prototype
```

打开 <http://127.0.0.1:4173/>；画册在 `/atlas/`。同一局域网评审时，绑定自己的局域网 IP，并用该 IP 打开。示例深链：`/#accounts`、`/#zone`、`/#worker`。无需构建，无真实云请求或凭据。

仅编写后台逻辑，且不改变用户可见的界面或交互时，无需更新设计稿、预览或对稿验收，按影响范围做功能测试即可。

1. **先改稿。** 新增页面或改变用户可见的界面、交互时，先在当前稿中从真实来路接好入口、主要操作、返回落点，以及相关空态、权限或错误状态。需要单独盘点的状态补到画册。只用虚构数据，尚未实现的能力标明规划。
2. **先看效果，再做原生。** 给出可点的预览直链，按用户任务走一遍。确认设计后在 Compose 中实现；不要把评审侧栏、图片热区或演示数据搬进 App。当前首页为 `home.png` 加热点，改首页布局须同步热点；编辑画册与当前稿时复用同一张首页图。
3. **按同一稿验收。** 从正式 App 入口核对外观、交互和返回路径；覆盖默认字号及窄屏大字号，保留原生截图和必要测试证据。原型能点通不代表 API 已实现或设备验收通过。设计变更回写这里，不以临时预览或截图替代源稿。
