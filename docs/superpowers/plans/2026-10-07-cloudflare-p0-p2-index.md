## 实施顺序

```text
P0 快照＋归属＋资格／协议准入
  ↓
P1 作用域 → 协议与策略 → 任务／产品端口 → 原生应用集成
  ↓
P1 阶段回归与授权试点验收
  ↓
P2 DNS定义 → DNS操作／Zone生命周期 → 原生闭环
  ↓
P2 批量／文件／扫描／DNSSEC／设置 → 54项证据核对
  ↓
P2 产品验收，再细化 P3–P9 各独立产品计划
```

P1基础接口稳定后才并行产品适配器；不让DNS／Workers／账单开发各自定义不兼容scope／page／任务状态。P2有外部阻塞时保持“未全量验收”，不能通过把未实现功能写成blocked就交差。

## 分工与文件所有权

遵守既有Paseo角色设置，不为本轮规划重复启动设计Agent；当前会话继续负责协调。

| 工作 | 默认角色 | 修改边界 |
| --- | --- | --- |
| 规格／公共接口／最终验收 | 方案设计，架构思考；当前会话承担相应角色时直接执行 | 契约、台账审查、集成检查与验收 |
| 工具、领域、适配器、平台与开发自测 | 日常工作 | 指定的tools／core产品包／platform包 |
| Compose页面、表单、导航交互 | Gemini | 指定的shared-ui产品包和获准的入口接线，不改领域接口 |
| 复杂协议／难题升级 | 高消耗工作 | 有明确问题、已尝试方法与证据之后使用，不默认承担普通测试 |

派发前读取实际最新profiles及notes，沿用保存的provider／model／thinking／mode，不根据配置名猜模型。优先复用相关会话；普通问题回原开发角色修复，测试验收不只转述子Agent报告。

公共文件单一集成负责人：`Models.kt`、`AppController.kt`、`ActionPolicies.kt`、`FlareGoViewModel.kt`、SQL迁移、导航入口。并行Agent可提接口变更建议，但不得同时无约束覆盖这些文件。

不采用每个小task新建Agent／workspace的默认开销模式。沿用用户指定角色分工，按产品工作包复用上下文并组织独立验收。
