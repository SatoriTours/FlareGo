# 云运维逐屏设计与交付计划（设计评审稿）

[离线界面板：21 个画面](../../app-design/cloudflare-operations.html) · [产品依据与长期范围](2026-11-21-cloudflare-product-roadmap.md)

## 导航与取舍

保持底部「总览／域名／资源／账单／账号」。不加第六个「运维」入口、不重做添加账号。资源→Worker/Pages/Tunnel；域名→选中站点→分析/安全与缓存；账号→云端审计；变更回执仍进本机操作记录。深层返回到原列表、筛选和滚动位置；换账号退出详情、取消旧请求并丢弃迟到结果。

设计板每张手机画面有入口、数据层级、动作和页下注释。页面正文不重复顶栏标题。资源名过长可换行；标识显示短码，点开看全值。详情页不用大插画：把最重要的事实放首屏，橙色仅作对比或提醒，不用颜色单独表达流量、失败或危险。分流条同时给文字比例；图表有等价可读列表。生产/预览用文字区别。参考暖白底与墨绿主操作，深色走既有 Material 主题；危险提交与普通导航视觉分离。每个可点区域至少 48dp；320dp / 2 倍字体时标签换行，重要值不截断，内容和操作可滚动。

## 五条用户路径

1. **判断线上版本。** 资源页沿用现有产品筛选（含 Workers），不默认同时拉所有产品。Worker 首屏先显示线上版本及分配，再列最近部署。点版本进版本详情；点部署进当次历史快照；完整版本列表允许出现「新建但未部署」的版本。来源字段缺失就省略，不把创建人当发布人。若无法把现代 Worker ID 与部署接口目标可靠对应，留在目录详情并解释原因，不拼接猜测的脚本名。
2. **检查 Pages 发布失败。** Pages 项目列表→项目详情→生产/预览分段→部署记录→部署详情。详情先呈现最终状态，再列返回的阶段、失败位置和提交信息；若官方只返回整体状态，不合成阶段。官网日志只用经过校验的官方目标，外链带标识。生产记录为空时不会拿预览成功补位。
3. **判断站点异常。** 从选定域名进分析。窗口选择「24 小时／7 天」；默认请求数，点带宽或 5xx 指标联动标题、图、单位及明细。点时段或「时段明细」看同一窗口的逐小时/逐日数值。5xx 占比明确分母；分母为零显示不适用。数据集不可用只影响该指标，不把断线、采样或 403 显示为零。
4. **变更版本。** 后续才在 Worker 详情提供「切换版本」。选择目标→当前/目标分配差异→确认（账号、Worker、全部流量、外部数据不回滚）→操作记录。取消不发写请求；失焦不提交，双击只接受一次，冲突要求重新确认，结果未知只给「核对部署」。首版只支持明确切换至一个已有版本，不做上传源码或自定义多版本百分比编辑。
5. **排障。** 安全事件列表按时间、动作筛选；点事件先看时间、动作及关联对象，再查规则详情，规则已删不影响事件事实。站点配置分别进入 WAF/缓存规则及证书详情；规则详情首屏呈现阶段、顺序、动作，再展开完整表达式，证书详情列覆盖范围与到期。Tunnel 从资源列表选中后看各连接器及最后观测；云端审计从账号进入，行内展开对象和动作。几类页面各需自己的权限与空态，不做一键全站扫描。

## 共同状态与验收契约

| 情况 | 页面反应 |
|---|---|
| 初次加载／后台刷新 | 首次用占位；刷新保留上次数据与更新时间，禁止叠加请求。 |
| 确认无记录／部分页 | 明示「尚无部署」或「暂无可见记录」；未读完显示「加载更多」，续页错误在列表底部重试。 |
| 403／未支持套餐 | 只有可证实的授权拒绝才提示相应权限；原因未知保留供应商拒绝。套餐不可用与权限不足分开，不建议盲目换 Token。 |
| 429／断网 | 明示可重试时间或手动刷新；保留同账号旧结果并标出时间；不触发重新授权。 |
| 删除／异步变化 | 提示目标已不存在，返回列表；历史条目不改写。写前快照失效不沿用原确认。 |

## 按可单独交付的版本排期

| 顺序 | 交付界面 | 接入和验证顺序 | 放行条件 |
|---|---|---|---|
| M1 Workers 只读 | 01–05、18 | 先用官方契约确认 ID、读取权限和分页→建部署/版本读取模型→接现有资源入口→实际入口验收；同时校准 README 的存储能力描述 | 刚创建的版本不被标为线上；单版本、分流、无记录、缺权、切账号通过；全程没有写请求 |
| M2 Pages 只读 | 06–09 | 先建项目、环境、部署数据→接项目和阶段列表→验证失败及部分返回 | 生产/预览不混淆，失败原因未知不杜撰，返回保留筛选，无部署重试按钮 |
| M3 站点分析 | 10–11 | 确认授权套餐可查询的数据集、时间窗口及采样口径→做 Zone 级查询与聚合→图与表读同一份结果 | 0、缺测和受限可区别；切时区、单位、窗口和账号不串数据；暂不做独立通知系统 |
| M4 受控发布 | 12–14 | 依赖 M1 只读核对和写权限证据；先实现冲突、重复提交与未知结果用例，再接预览、确认与结果核对 | 需获授权的隔离资源验证实际写入；未具备资格则保持只读，不以测试替身解锁生产 |
| M5 移动排障 | 15–17、19–21 | 先规则/证书只读，再接事件关联；Tunnel、审计各独立交付，不互相阻塞 | 规则顺序、证书作用域、连接器过期、审计来源正确；无对应套餐只标外部限制 |
| 贯穿各期：存储补证 | 复用现有 R2/KV/D1，不新造界面 | 对已有入口逐项记录真实可用、未授权、仅测试通过；按授权在隔离资源补证 | 缺证路径保持关闭，不能用演示成功替代生产资格 |

M1 是下一次拟开发范围；其余为排序，不是同时开工或发布日期。每个版本按现有 shared-core 产品客户端/权限/作用域、shared-ui 原生页面、app Android 交互测试拆职责，由同一实现负责人贯通。先测最容易误导用户的反例，再实现，最后独立验收真实 App 入口、返回、深色及大字体；自行测试仅在指定 PVE 环境，既有 CI 不变。真实云写入、购买、读取敏感日志均不含在设计授权中。
